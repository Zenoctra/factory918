## 9. Milestones for the implementing model

Each milestone ends with its acceptance checks run and their output pasted into the PR that lands it (the factory repo uses its own PR contract from day one). The order matters: nothing is written for another model before the writing skills are loaded, and no template prose is written before the philosophy and manual exist to write it against.

**M0 — Ground truth and tools (½ day).** Read `docs/knowledge/core/PHILOSOPHY.md` whole and `MANUAL.md` whole; read this spec whole; read `INDEX.md`. Load `writing-for-agents`, `technical-writing`, `unslop` and `deslop` from `.claude/skills/` (§0 rule 6). Record tool versions (`vp`, `vite-plus`, `@oxlint/plugins`, `ast-grep`, `uv`, `ruff`, `pyright`, `claude`). Confirm: `vp create --no-interactive` flags, `vp hooks enable`/`status`, multi-glob `staged`, `setup-vp@v1` inputs, `@oxlint/plugins` exports, `ast-grep` config keys and `scan`/`test` behaviour, `setup-uv` inputs, the ruff `select` codes against the installed version, Claude Code hook events used, and `disable-model-invocation` semantics. Acceptance: `M0-findings.md` with one line per fact and its source URL; every deviation from this spec listed with the fix you intend.

**M1 — Vendor the skills (½ day).** §5.1–5.2 and the patch list §5.4 as `patches/` plus `SOURCES.md` with exclusions. Acceptance: 69 skill directories minus `no-comments` (68) with no duplicate `name:`; no `pstack:` namespace residue; Matt's planning entry points still carry `disable-model-invocation: true`; every pstack action skill does not; `spec-review` renamed; the Ticket playbook and router line present; `opening-a-pr.md` no longer mentions `/no-comments`.

**M2 — The truth (1 day).** `docs/knowledge/` from `tools/build_knowledge.py` (all core documents, both specs, the three pages, the notes; chunked; `INDEX.md`); the three glue skills (`factory918`, `factory-start`, `knowledge`) written against `writing-for-agents`; the session mandate. Acceptance: `INDEX.md` lists every file with a line count; no chunk exceeds 240 lines; each chunk's mini-TOC line numbers resolve to the headings they name (spot-check five with `sed -n`); in Claude Code inside the factory repo, `/knowledge why do comments stay` answers with a `DECISIONS.md:line` citation and reads fewer than 200 lines in total (check the transcript); `/factory918` returns an entry point for each row of its table when prompted with that situation.

**M3 — Template files (1 day).** §4 and §7, with `AGENTS.md` written last because it points at everything else, in Manuel's voice, passed through `writing-for-agents`; `docs/factory918/` slim copies; `docs/agents/models.md` and `ledger.md`; profiles' files under `profiles/`. Acceptance: on a fresh `vp create vite:monorepo --no-interactive` project, `factory918 apply` then `factory918 doctor` fails only on the "slots filled" and label checks; a deliberately unformatted file lands formatted after `git commit`; a `// TODO later` comment fails `vp lint`; `console.log` fails `ast-grep scan`; a stale `// oxlint-disable` fails `vp lint`; CI on a throwaway repo goes green, then red when a test is broken on purpose.

**M4 — Hooks and the Day-0 flow (½ day).** §7.4 and `/factory-start`. Acceptance: `/factory-start` on the M3 project asks only the eight decisions, writes every slot, creates `ledger.md`, and `factory918 doctor` then passes every check; typing `/grill-with-docs` sets the phase to planning and the next prompt's context shows the planning line; `/mode-build` flips it; a file written by the agent is formatted before the next tool call; `git push origin main` and `git reset --hard` are refused with a visible BLOCKED message; `git push origin feat/x` is allowed; the mandate appears after `/clear` and names `factory918`.

**M5 — GitHub layer (½ day).** §7.8 plus the branch-protection wizard. Acceptance: labels exist; a PR gets a `size:*` label; `main` refuses a merge while `Check` is red; the PR template renders; a seeded ticket run with `/poteto-mode "#1"` reads the issue, checks blockers, raises falsifiability notes, runs the Feature playbook and reaches Opening a PR with `Closes #1` and a Verification section, never blocked by "skill cannot be invoked"; `/unslop` fires on its own when the agent drafts the PR body.

**M6 — Profiles (1 day).** §7.10–7.11. Acceptance, React Native: `factory918 apply --profile react-native` on the monorepo adds an Expo app that `vp check`, `pnpm typecheck` and `vp test run` cover; the fingerprint workflow runs on a PR touching `apps/mobile` and applies its label when a native dependency is added; the primary agent can launch a simulator and leave a screenshot in `.artifacts/`. Python: `factory918 apply --profile python` adds `python/<name>` with a passing `python.yml`; `print("x")` in a module fails `ast-grep scan` and `ruff check`; `os.system` fails `ruff check` with the banned-API message; `*.py` is formatted on commit in the monorepo; `uv audit` runs.

**M7 — `update` and `sync` (1 day).** §8.2. Acceptance: on a project at template v1, edit `AGENTS.md` locally, delete `docs/agents/feedback-loops.md`, bump the template to v2 (which changes `AGENTS.md` elsewhere and adds a file); `factory918 update` keeps the local edit, applies the template change, adds the new file, does not resurrect the deleted one, refreshes `docs/factory918/`, and produces a `.factory-merge` file only where lines actually collide. `factory918 sync` against a newer open-pstack tag re-applies all §5.4 patches with no manual edits and reports any patch that no longer applies.

**M8 — First real project and a retro (ongoing).** Apply to one real product monorepo. After two weeks: `/reflect`, read the ledger, promote the first recurring correction to a rule at the strongest rung that holds it; record it in `DECISIONS.md` under Provisional. That is when Factory918 stops being copied opinions and starts being Manuel's.
