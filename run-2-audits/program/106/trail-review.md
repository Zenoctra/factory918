## Flags

1. **The "inside the fix" rule matches line text, not location** (Terms, and `outside()` in `review-comment.sh`). The fix lines are a set of trimmed strings with a four-character floor. A hard finding that quotes a marked line elsewhere in the PR whose text happens to equal a fix line (`return nil`, `} else {`, `exit 1`, an import, a repeated guard) is judged inside, and round three goes fix-only while that finding's real location is never re-read whole-diff. The design states every uncertain case falls toward outside, toward more review; this case falls the other way, and it is the only rule in the ticket that Manuel's quoted condition ("at least one pass with zero new happy path hard bugs") rests on. The four-character floor is a weak mitigation, grafted in from the lower-tier candidate with no argument recorded against this failure mode.
2. **Zero hard items prints the FO line** (table B row 1C, explicit). A round-two comment whose reports are empty because a reviewer lane produced nothing, crashed, or was briefed wrong is indistinguishable from a round that looked and found nothing, and it licenses fix-only from round three on, permanently (stickiness needs no code). Nothing in the tail distinguishes "no hard item of two reported" from "no report".
