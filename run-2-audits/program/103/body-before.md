## Acceptance criteria

- [ ] A fixture set is committed under `tests/eval/reviewer/`: for each of the twelve rounds, the Standards brief and the Spec brief exactly as `review-brief.sh` produced or reproduces them, and a `labels` file naming, per brief, each hard finding that led to a fix in that round in one line, with the axis that reported it; a brief with no labeled finding is in the set too, since a false hard finding on it counts against a model.
- [ ] A runner under `tests/eval/reviewer/` re-runs one brief against one named model N times through provider dispatch (a Claude descriptor natively, a Codex descriptor through the external runner), writes each report and a receipt with input, output and cache tokens and wall clock, and scores the report: recall of the labeled findings, the count of unlabeled hard findings, and a context failure when the model refused, truncated or returned no `hard findings:` line. A report without that line is scored as a failure, never as zero findings.
- [ ] Results exist for `claude:sonnet` (the strongest Sonnet the provider serves), `claude:opus` at the Opus 5 revision, `claude:fable` at 5.1, Opus 5.5, `codex:gpt-6-terra` and `codex:gpt-6-sol`, each over every brief with N of at least 3; the three new models' descriptors and matrix rows are added to `provider-dispatch.md` from what the providers report, and a model this harness cannot reach is recorded as a dropout with its receipt, not skipped silently.
- [ ] A results table per model in a dated `docs/M0-findings.md` section: recall, unlabeled hard findings per brief, mean output tokens, mean input tokens with cache reads separated, mean wall clock, and context failures, with the run count; the raw reports and receipts stay under `.scratch/eval/reviewer/` and are not committed.

- [ ] The `## Design` section on this ticket carries the runner's usage and signature and a small scenario table for its refusals before the runner is written, and `tests/eval/reviewer/` has one assertion per cell.
