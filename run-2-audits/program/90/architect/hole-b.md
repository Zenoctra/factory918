## Hole 1: the rule

**The rule.** A `hole:` field is the text `hole:` followed by a space and one of the reference grammar's three keywords as a whole word (`table`, `design`, `criterion`), on a judgment item's own line, when no well-formed `fixed:` or `ticket:` field ends the line. Any other line holding the text `hole:` carries no field: it is prose, as a malformed `cites:` (table A row 17) and a malformed `fixed:` are prose today. A field so detected is well formed only when it is `hole: <reference>` ending the line; otherwise it is refused, so a mark written with the grammar's own words is never silently dropped.

One line of code, the second grep of `holed()`:

```sh
holed() { items "$dir/judgment.md" "$1" | grep -vE "$ending" | grep -E 'hole: (table|design|criterion)([[:space:]]|$)' || true; }
```

The rule a reader holds: *the keyword makes the field; the `$` anchor makes it valid.* It cannot admit both `hole: cell 12A` (refused) and `Not a design hole: the table stands.` (prose), because the only text that tells them apart is the word after `hole:`. Column A wins the collision: the prose is written on the happy path of judging (it is the phrase this ticket teaches), while a keyword-less mark is a copy the judge made up, since the mark repeats a `spec:` value the script already validated to one of the three forms, and the comment it produces carries no `restart` line for the orchestrator to miss.

## Rejected

- Keep today's loose `hole:` grep and only improve the message: the collision sits on the happy path of judging, and it costs a refusal and a rerun for prose that was right.
- Treat `hole:` exactly like `fixed:` and `ticket:` (a field only when well formed and `$`-anchored): every malformed mark is then dropped in silence, which is the risk the loose grep was bought for.
- Anchor the field to a sentence boundary (`. hole:`, or the start of the trailing fields): it depends on the reason's punctuation and is not a rule a reader can hold.
- Give the mark a sigil or backticks (`hole=`, `` `hole: ...` ``): it makes `hole:` unlike the two fields it sits beside, and changes columns B and C.
- Extend the keyword set with near misses (`cell`, `row`, `criteria`): a blacklist that drifts and never closes.
- A fourth reference form for the no-ticket case (`spec: standard <file:line>`, `spec: diff <path>`): it duplicates `Documented step:`, which already carries the `file:line`, and adds a form to a grammar three places copy.
- Let `design <signature>` absorb the no-ticket case: its grammar takes arbitrary text, so the reference would be invented, which is the finding itself.
- Refuse a review with no ticket: the no-spec path is documented (`SKILL.md:38`) and the sweep form has no ticket by construction.
