## Hole 1: the rule

**The rule.** On a judgment item's line that does not end in a `fixed:` or `ticket:` field, the text from the last `hole:` to the end of the line is the `hole:` field; a line with no `hole:` text carries no mark. The field is a mark only when it reads `hole: <ref>` in one of the three forms; any other value is a malformed mark and is refused with a message that shows the value and says how to correct it, so a hole is never dropped silently and a reason that happens to say "hole:" is reworded in one edit. This is what `holed()` and the E check do today; the hole was the undefined term and a refusal that named the field without showing it. No `$`-anchoring for `hole:`: `fixed:` and `ticket:` can afford it because a malformed one costs one counted item; a malformed `hole:` that fell through as prose would send a design hole down the fix-on-the-PR path, which the ticket's Decision forbids.

Why not the anchored rule: it makes column E "as A", so `hole: table 2` counts as an ordinary Act on item, prints no `restart`, and the caller fixes a hole on the PR. That is the one outcome the ticket exists to prevent, and it is silent. A prose collision refused with a message saying how to correct it is not a finding by the review's own definition, so the cost of the wide rule is one reworded reason per collision, and the collision is rare: the judgment's reason is one line and "hole" without a colon is free.

## Rejected

- Anchoring `hole:` at `$` like `fixed:`: a malformed hole becomes a counted item with no `restart`, the silent fix-on-the-PR path the ticket forbids.
- Recognising `hole:` only when its value starts with `table `, `design ` or `criterion `: `hole: cell 12A` then drops silently, and the reader holds a second list.
- A fourth `spec:` form for the no-ticket case (`spec: standard <file:rule>` or `spec: none`): it names a thing that is not an artifact the work was built against, so a hole on it would return to architect with nothing to amend.
- Writing the spec rule into the no-spec Standards brief with a "when there is a ticket" clause: the reviewer has no ticket to check the clause against, and the layout test would carry two shapes for one sentence.
- Refusing a no-spec review's `hole:` before the placement and grammar checks: a prose collision under Noted would then get the no-spec message, which says the wrong correction.
- Leaving 1G's message as it is: the finding names both refusals, and under Noted the prose collision's correction is "reword", which the current text does not say.
